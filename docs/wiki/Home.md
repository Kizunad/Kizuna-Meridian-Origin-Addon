# 出身

玩家第一次进世界时，服务端给他抽几个出身（默认三个），弹出界面让他选一个。选定以后游戏里没有办法改。
每个出身带一份天赋、一份天生的麻烦，有得有失。

本仓是框架，只管三件事：

- **有哪些出身**：数据包里的 JSON，加新出身不改代码；
- **谁选了哪个**：记在玩家身体的附属进度里，随身体存盘，死了重生不丢；
- **把参数交给实现方**：天赋和麻烦各有类型，类型由管那块机制的附属登记，本仓不带任何具体天赋。

给别的附属用的接口见 [Integration](Integration.md)。

## 玩家看到的

- 进服后几个 tick，界面自己弹出来：几张并排的纸，每张上半是来历，下半照实列天赋和天生的麻烦。
- 点某一张的「就是它」，底栏问一遍「定了就不能改」，确认才算数。
- 可以「先不选」。没选之前没有天赋，也没有出身带来的麻烦；下次进服界面再弹，也可以用 `/meridian body origin` 自己打开。
- 选过以后 `/meridian body origin` 打开的是只读的那一张。
- 抽到哪几个由世界种子和玩家决定，退出重进还是那几个，刷不出另一组。
- 多人时各人一份，互不影响。
- 窗口窄得并排放不下时，几张纸改成上下排，可以滚动。并排时天赋和麻烦始终露着，纸太高就只让来历自己滚；
  来历缩到最少还是放不下（天赋和麻烦字多、窗口又矮），也改成上下排。

## 出身数据

路径：`data/<命名空间>/meridian_origin/origin/<名字>.json`，出身 ID 是 `<命名空间>:<名字>`。

```json
{
  "weight": 10,
  "icon": "minecraft:iron_sword",
  "group": "spirit",
  "talents": [
    { "type": "<天赋类型 ID>", "params": { } }
  ],
  "threats": [
    { "type": "<威胁类型 ID>", "params": { } }
  ]
}
```

| 字段 | 必填 | 含义 |
|---|---|---|
| `weight` | 是 | 抽选权重，正整数 |
| `icon` | 是 | 界面上的图标，一个物品 ID |
| `group` | 否 | 互斥组。同组的出身一次抽选里至多出一个 |
| `talents` | 是 | 数组，可以为空，至多 8 项。每项写 `type`，`params` 省略时按空对象交给类型的解析器 |
| `threats` | 是 | 同上 |

- 每个 `type` 都要有附属登记过，`params` 由登记方的解析器核对。
- 服务器启动时有一份出身不对就启动失败，报错写明是哪个出身的哪一项。
- `/reload` 以后重读；新数据不对时沿用重载前的出身，并打错误日志。
- 界面文字不写在 JSON 里，由客户端按出身 ID 取语言键：

| 语言键 | 内容 |
|---|---|
| `origin.<命名空间>.<名字>.name` | 出身名 |
| `origin.<命名空间>.<名字>.story` | 来历，沉浸口吻的叙事 |
| `origin.<命名空间>.<名字>.talent.<序号>` | 第几项天赋的界面文字，序号从 1 起，和 `talents` 一一对应 |
| `origin.<命名空间>.<名字>.threat.<序号>` | 第几项麻烦的界面文字；`threats` 为空时界面写「无」 |

## 玩家记录

存在玩家身体的附属进度里，键 `meridian_origin:origin`：

| 字段 | 含义 |
|---|---|
| `offered` | 抽出的候选出身 |
| `chosen` | 选定的出身，没选为空 |
| `chosen_at_millis` | 选定时的世界时钟 |
| `granted` | 已经发过的一次性天赋，写作 `<出身 ID>#<talents 下标>` |
| `draw_round` | 第几轮抽选，正常是 0；只有调试指令让玩家重抽时加一 |

- 身体由别的附属在进服时建，先后没有保证。所以进服后每 tick 试读一次，读到身体才抽选、弹界面。
- 候选里有出身被数据包删掉、或被配置禁用：没选的玩家把缺的补抽上，其余不动。
- 选定的出身被数据包删掉：记录不动，它的天赋和麻烦不生效，日志提示一次。

## 指令

Framework 不许附属在 `/meridian` 下开新的二级节点，所以挂在现有分支下。字面量和出身 ID 都能 Tab 补全。

| 指令 | 权限 | 作用 |
|---|---|---|
| `/meridian body origin` | 玩家 | 没选就重新弹选择界面，选过就打开只读的那一张 |
| `/meridian debug origin show [<targets>]` | op | 看选定的出身和抽到的候选 |
| `/meridian debug origin set <target> <origin>` | op | 直接定出身，不看候选；照常发一次性天赋、通知各附属 |
| `/meridian debug origin offer <target>` | op | 清掉候选和选定，换一轮重新抽、重新弹界面；已发过的一次性天赋不收回 |

调试指令只为测试，不算「改命」的途径。

## 配置

`config/meridian-origin.toml`，第一次启动导出默认文件，之后只读；三个键都要写，有不认识的键拒绝启动。

| 键 | 默认 | 含义 |
|---|---|---|
| `selection` | `true` | 关掉以后不弹界面、不接受选定，所有人都没有出身。已经选过的玩家不受影响 |
| `offer_count` | `3` | 一次抽几个，1～8。能抽的出身不够时有几个给几个 |
| `disabled` | `[]` | 不参与抽选的出身 ID。已经选了它的玩家照旧 |

## 进度

- 触发器 `meridian_origin:chosen`：定下出身时触发。条件可写 `"origin": "<出身 ID>"` 只认一个出身。
- 本仓带一条进度「命格」，挂在进度树「道上的人」下面，定下任意出身就拿到。

## 依赖

硬依赖：Framework、Fabric API、owo-lib。玩家身体由完整装配里的 Human 提供，经 Framework 的 `meridian_health_host`、`meridian_activity_host` 两个入口读写；启动时没有身体宿主就失败。没有「未安装时」的退路。

## 验证

```
./gradlew --no-daemon test build
./gradlew --no-daemon :fabric:runGametest -PgametestRunDir=<新目录>
xvfb-run -a ./gradlew --no-daemon :fabric:runClientTest -PgametestRunDir=<上一步的目录>
```

- `server` 单测：抽选（同种子同结果、权重、互斥组、补抽）、记录读写和规则、配置。
- `fabric` 单测：出身 JSON 解析和各种写错的情形。
- GameTest（测试出身和测试类型，假玩家走正式进服）：
  - 进服收到三个候选，退出重进还是那三个；
  - 选定写记录、一次性天赋只发一次、通知一次、进度拿到，重进不再弹界面；
  - 候选以外的、不存在的、解不开的选定都不接受，选定以后不能再选；
  - 常驻天赋和威胁参数查得到；
  - 一次性天赋这次没发成，下次进服补发；
  - 四条指令、补全和权限；
  - 配置关掉选择后不发候选、不接受选定。
- 客户端截图测试：真客户端进单人世界，三张样例出身的界面、确认底栏、选定后只读的一张各截一张图。
  窄窗口加 `-PoriginClientSize=480x720 -PoriginClientShots=narrow` 再跑一次。
